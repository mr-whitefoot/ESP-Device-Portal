# Правила работы с репозиторием

Значения слов проекта («образ», «прошивка», «зеркало», «парк», `Button mode`)
собраны в [GLOSSARY.md](GLOSSARY.md).

## Работа с физическими устройствами

- `Gate` не входит в область этого репозитория. Не менять для него код или
  конфигурацию, не собирать и не загружать прошивку без отдельного явного
  разрешения владельца именно на работу с `Gate`.
- Если проверка требует прошивки нескольких устройств, первым прошивать реле.
  Реле можно использовать для проверки изменений без дополнительного
  подтверждения владельца.
- Датчик DS18B20 прошивать только после явного подтверждения владельца на
  конкретное обновление и только стабильной сборкой. Диагностические,
  предварительные и непроверенные сборки на датчик не загружать.
- Адреса устройств и секреты не добавлять в репозиторий. Локальные адреса
  хранятся в `platformio_override.ini`, данные брокера — в
  `tools/broker.ini`; оба файла игнорируются Git.

## Проверка изменений

- Чистую логику проверять командой `pio test -e native`.
- Правки `web/fw.js` проверять командой `node test/web/fw_test.js`. Скрипт
  страницы обновления живёт на зеркале, а не во флеше: компилятор и проверка
  размера образа его не касаются, а между кнопкой `Install` и записью во флеш
  ничего другого нет.
- Изменения общего ядра проверять сборкой всех конечных образов:
  `pio run -e esp01_relay`, `pio run -e d1_mini_relay`,
  `pio run -e esp07s_relay8`, `pio run -e sonoff_basic_relay`,
  `pio run -e esp01_ds18b20` и `pio run -e d1_mini_ds18b20`. Диагностическое окружение
  `esp01_relay_metrics` проверять вместе с полным релизным прогоном.
- Следить за строками `OTA headroom` и `gzip:` в выводе сборки. Успешная
  линковка без прохождения OTA-предела своей платы недостаточна для любого
  ESP8266. Самый тесный образ — `esp07s_relay8`: запас у него порядка сотен
  байт (точное значение — в строке `OTA headroom`), поднять `custom_ota_max_size` нельзя без потери espota и ручной
  заливки на однометровых платах (ADR 0015).
- Перед выпуском релиза добавлять секцию в `CHANGELOG.md` с заголовком-номером
  версии. Её текст уходит и в тело релиза, и на страницу обновления устройства,
  поэтому несколько строк без разметки. Забытую секцию релиз ловит до сборки.
- Перед работой с железом использовать чек-листы из
  `docs/runbooks/verification.md`.
