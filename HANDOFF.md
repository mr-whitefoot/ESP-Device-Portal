# Handoff: поддержка восьмиканальной платы ESP-07S

Обновлено: 2026-08-06

## Цель

Добавить в этот репозиторий стабильную прошивку для соседней восьмиканальной
релейной платы на ESP8266 ESP-07S, сохранив существующие образы ESP-01, D1 mini
и DS18B20 совместимыми по поведению и MQTT-топикам.

Рабочая ветка: `feature/esp07s-relay8`.

## Область работы

- новый профиль платы `esp07s` с корректной разметкой 4 МБ и контролем OTA;
- новое окружение `esp07s_relay8` без адресов и секретов в репозитории;
- отдельная реализация устройства `device_relay_bank` для восьми каналов;
- несколько независимых сущностей Home Assistant на одном физическом устройстве;
- портал, подписи каналов, восстановление состояний и таймеры с выбором канала;
- native-тесты, сборки всех конечных образов, CI, release и runbook.

Вне области без отдельного разрешения: `Gate`, прошивка DS18B20 и любые
загрузки на физические устройства. Проверка на железе, когда до неё дойдём,
начинается с релейной платы.

## Принятые решения

1. Соседний каталог называется `ESP32-Relay-Portal`, но текущая плата и код
   используют ESP8266 ESP-07S. Поддержка настоящего ESP32 в эту ветку не входит.
2. Восьмиканальный банк будет отдельным типом устройства, а не набором
   условных веток внутри стабильного одноканального `device_relay`.
3. MQTT должен представлять восемь стабильных сущностей с идентификаторами
   `relay_1` ... `relay_8`. Пользовательские подписи не должны участвовать в
   топиках или `unique_id`.
4. Состояние восьми каналов публикуется одним JSON в общем state topic;
   discovery и command topic у каждого канала свои, availability общий.
5. Для одноканальных устройств пути топиков, `unique_id` и `object_id` должны
   остаться прежними.
6. Профиль ESP-07S использует штатную разметку `eagle.flash.4m1m.ld`; старый
   принудительный `eagle.flash.1m.ld` из соседней рабочей копии не переносится.

## Найденные трудности и риски

- Восьмиканальные изменения соседнего проекта находятся в незакоммиченной
  рабочей копии. Она используется только как источник распиновки и требований.
- Текущий `CoreMqttClient` хранит ровно одну подписку и один callback. Для
  восьми командных топиков потребуется ограниченный таблицей набор подписок.
- Текущий статический контракт описывает одну Home Assistant сущность. Его
  расширение затрагивает общее ядро, поэтому обязательны сборки всех образов.
- GPIO0 и GPIO15 являются загрузочными GPIO ESP8266. Корректность их внешних
  подтяжек определяется схемой платы и не может быть исправлена прошивкой.
- Старый восьмиканальный код создаёт восемь объектов с GPIO0 до `setup()` и
  таймерами управляет только первым реле. Эту реализацию переносить нельзя.
- Текущий образ реле занимает около 472 КБ. Для ESP-01 запас мал, поэтому даже
  обобщение MQTT должно контролироваться сборкой ESP-01; у ESP-07S с 4m1m запас
  существенно больше.
- Во время работы отдельно изменился `tools/broker.ini.example` (`10.0.1.5` на
  `192.168.1.10`). Это не относится к реализации платы; изменение сохранено как
  пользовательское и не должно попасть в тематический коммит без решения владельца.
- `pio project config` разобрал новое окружение успешно, но завершение команды
  попыталось записать телеметрию в `~/.platformio/.cache`, что запрещено
  песочницей. Для итоговых запусков PlatformIO может потребоваться разрешение
  на его штатный домашний кеш; это не ошибка конфигурации проекта.
