# Восстановление устройства, которое не поднялось

Когда после обновления устройство не появилось в сети: нет ответа на ping, нет
портала, нет точки доступа. Порядок ниже вырос из случая с ESP8285 в режиме
`qio` ([ADR 0016](../adr/0016-esp8285-flash-mode-dout.md)), где обновление
выглядело виновником, а виноват был режим флеша.

## Что считать установленным

Успех заливки уже говорит многое. Устройство само сверяет md5 принятых байт
и только потом отдаёт команду загрузчику, поэтому `Update success` (или
`Result: OK` у espota) означает: образ дошёл целиком и цел. Остаются два шага
без сети -- копирование загрузчиком (несколько секунд, переписывается и сам
загрузчик) и первая загрузка нового образа. Порча файла при передаче исключена.

## Порядок действий

1. Снять и подать питание заново. После `ESP.restart()` на ESP-01 линия GPIO2
   могла остаться притянутой вниз внешней шиной; холодный старт это лечит и
   стоит ничего.
2. Посмотреть, не появилась ли точка доступа устройства. Если да, прошивка
   жива, и вопрос только в Wi-Fi.
3. Подключить USB-UART (74880 бод для сообщений ROM, потом 115200) и смотреть
   вывод после сброса. Баннер `boot start` есть -- прошивка стартует; нет, а ROM
   пишет `boot mode:(3,1)` -- загрузка идёт из флеша, перемычки в порядке.
   Остановка после `rf cal sector` без баннера -- признак неверного режима
   флеша.
4. `esptool flash_id` называет чип. `ESP8285` со встроенной флеш-памятью требует
   `dout`; байт 2 заголовка образа во флеше должен быть `03`. `00` (qio) на этом
   чипе -- причина.
5. При сомнении в содержимом флеша прочитать область приложения
   (`esptool read_flash`) и сверить с файлом образа побайтно. Совпадение
   означает, что копирование прошло, и дело не в нём.

## Лечение

Заливка по UART тем же образом с верным режимом. Окружения проекта задают режим
сами (`dout` у ESP-01 и Sonoff Basic R2), поэтому достаточно обычного
`pio run -e <окружение> -t upload` с `upload_protocol = esptool` и портом
переходника (см. README, «Первая прошивка чистого модуля»). GPIO0 на землю в
момент подачи питания.

Настройки при этом сохраняются: пишется только область приложения, LittleFS не
затрагивается. Если нужна чистая плата, стирание флеша делается отдельно и
осознанно.

По воздуху режим флеша не исправить: `Updater` переписывает его байт из
конфигурации работающей прошивки. Это лечится только UART.

## Что учесть дальше

- Режим флеша виден в загрузочном баннере полем `flash=`; на всём парке его
  можно проверить по `/log`, не разбирая устройства. Страница портала, открытая
  в браузере, опустошает кольцо лога при каждом опросе, поэтому баннер ловится
  с закрытой страницей или по Serial.
- Сжатый образ ([ADR 0014](../adr/0014-compressed-ota-images.md)) байты режима
  и размера флеша не получает патчем и обязан быть собран под ту же плату.
- Образ, объявивший неверный размер при заливке `.gz`, может затереть собственный
  источник. Это тоже лечится только UART; поэтому проверку сжатой заливки
  проводят на однометровой плате ([verification.md](verification.md), раздел 3b).
