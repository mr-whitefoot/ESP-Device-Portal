# 0016. Профили с ESP8285 собираются в режиме флеша DOUT

Статус: принято.

## Контекст

Манифест PlatformIO для платы `esp01_1m` задаёт режим флеша `qio`. Под этим
профилем в парке оказался не только настоящий ESP-01 с внешней флеш-памятью,
но и ESP8285 со встроенной. Её флеш работает только в `dout`: линии, которые
`qio` занимает под два дополнительных бита, у неё разведены иначе.

Пока образы собирались на старой платформе, SDK это терпел. С переходом 4.3.1 на
`espressif8266@4.2.1` (Arduino core 3.0.2 → 3.1.2) перестал: датчик DS18B20
после обновления по воздуху замер на инициализации радио сразу после
`rf cal sector`. Диагноз поставлен по UART: `esptool flash_id` назвал чип
ESP8285, образ во флеше совпал с файлом побайтно, а байт режима в заголовке был
`0x00` (QIO) вместо `0x03` (DOUT). Тот же образ, залитый с `--flash_mode dout`,
вернул устройство к жизни — изменился один байт заголовка. Хроника и
отброшенные версии причины — в `HANDOFF.md`, раздел «Разбор по UART: OTA ни при
чём, модуль — ESP8285 в режиме QIO».

Ошибка воспроизводит сама себя: `Updater` при OTA переписывает байт режима из
конфигурации работающей прошивки, поэтому по воздуху режим устройства не
меняется никогда.

## Решение

Профиль `[esp01]` собирает образы в `dout` (`board_build.flash_mode`), хотя
манифест платы предлагает `qio`. Профиль `[sonoff_basic]` тоже держит `dout`
явной строкой: манифест платы задаёт его сам, но режим стоит одного байта
заголовка и целого устройства, замершего на `rf cal sector`. Загрузочный баннер
печатает режим полем `flash=`, чтобы его не приходилось узнавать, сняв
устройство и подключив UART.

Профиль `[esp07s]` намеренно не менялся: тип чипа на той плате не проверялся.

## Последствия

Размер образов не меняется. Цена — чуть более медленное чтение флеша: данные
идут по одной линии вместо четырёх.

Правка защищает только тех, кого прошивают по UART. Уже работающее устройство с
неверным режимом по воздуху не исправить: единственный путь — UART с
`--flash_mode dout`.

Сжатый образ ([ADR 0014](0014-compressed-ota-images.md)) `Updater` не
подстраивает под устройство: для `.gz` байты режима и размера флеша в
заголовке не патчатся. Поэтому сжатый образ обязан быть собран в том же режиме,
что и прошивка на устройстве.

Источники: комментарий у `[esp01]` и `[sonoff_basic]` в `platformio.ini`;
`HANDOFF.md` (инцидент DS18B20); коммиты `e7ca636` и `7a32fdd`;
[CHANGELOG](../../CHANGELOG.md) и [разбор версии 4.4.0](../history.md).
