# 0013. Приём образа по HTTP делает прошивка, а не CustomOTA

Статус: принято.

## Контекст

Заливку образа через портал выполнял `CustomOTA` из GyverPortal, подключаемый
вызовом `portal.enableOTA()`. Он объявляет `Update.begin()` не размер
присланного файла, а `getFreeSketchSpace() - 0x1000`.

Разница не косметическая. `Update.begin(size)` размещает область стейджинга в
конце области скетчей, отступив назад на объявленный размер, поэтому лишний
сектор в объявлении съедает 4 КБ у предельного образа. На однометровых платах
это и есть весь запас: релиз 4.3.0 не встал на реле, промахнувшись мимо предела
на 48 байт, — при том что espota тот же образ принимает, потому что объявляет
настоящий размер.

Отдельно выяснилось, что образы из CI на 3,3 КБ больше локальных: платформа
не была прикреплена, локально стояла `espressif8266` 3.2.0, в CI — 4.2.1. После
прикрепления запас `esp07s_relay8` оказался равен 112 байтам, то есть места на
исправление в лоб не было вовсе.

## Решение

`portal.enableOTA()` не вызывается; приём образа живёт в `lib/core/core_ota.h`
и регистрирует единственный маршрут — `POST /ota_update`. Страницу по GET
отдаёт обычный обход портала, как и всем остальным страницам.

Настоящий размер приходит параметром `?size=` от скрипта страницы обновления,
он же приносит `?md5=` из манифеста. Параметры берутся из строки запроса, а не
из формы, и это существенно: разбор multipart зовёт обработчик загрузки по ходу
приёма тела, когда аргументы формы ещё не собраны, тогда как аргументы строки
запроса к этому моменту уже разобраны.

Ручная заливка файлом ни размера, ни хэша передать не может и работает по
прежнему правилу `CustomOTA` — она остаётся путём отката и заливки
непубликованной сборки.

Значение `?size=` не проверяется на разумность нарочно: слишком большое отвергнет
сам `Update.begin()` с `UPDATE_ERROR_SPACE`, а слишком маленькое оборвёт запись
на превышении — перелиться за объявленное `Update` не даёт. Обе ветки проверены
на железе.

Пустой POST без файла считается ошибкой явно. Обработчик загрузки в этом случае
не зовут ни разу, и по одному лишь отсутствию ошибки запрос выглядел бы удачным
обновлением — со страницей «success» и перезагрузкой.

## Последствия

Отказ от `CustomOTA` освободил 2128 байт даже вместе с добавленным своим кодом:
там своя страница, свой JS и обновление файловой системы, которыми прошивка не
пользуется. Запас `esp07s_relay8` вырос со 112 байт до 2176, и предельный образ
для портала стал на 4 КБ больше — ровно та причина, ради которой всё делалось.

`?md5=` даёт единственную сквозную проверку образа на пути зеркало → браузер →
устройство. Посчитать хэш в браузере нельзя: портал работает по http, а
`crypto.subtle` доступен только в защищённом контексте. Теперь считает
устройство, а ожидаемое значение приходит из манифеста по HTTPS.

Со своим обработчиком открывается дорога к заливке `.bin.gz` через портал:
при объявленном настоящем размере область стейджинга отступает достаточно, и
распакованному образу остаётся больше сотни килобайт запаса вместо нынешних
четырёх. Это отдельный шаг: зеркало пока публикует только `.bin`.

Цена — свой код на пути прошивки, то есть в самом опасном месте проекта.
Поэтому его ветки проверяются на железе по матрице из runbook, а не только
сборкой.
