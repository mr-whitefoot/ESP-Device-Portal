# 0010. Профили плат отделены от типов устройств

Статус: принято.

## Контекст

Первая релейная сборка работала только на ESP-01, поэтому GPIO0 был зашит в
`device_relay.h`, а общая секция PlatformIO одновременно описывала плату ESP-01
и общие свойства ESP8266. Добавление D1 mini с отдельным релейным GPIO
потребовало разделить то, что определяется платой, и то, что определяется
типом конечного устройства.

## Решение

- `[esp8266]` хранит общую платформу, framework, библиотеки, скрипты и версию.
- `[esp01]` и `[d1_mini]` хранят board ID, разметку флеша, протокол загрузки и
  `custom_ota_max_size`.
- Конечное окружение выбирает профиль платы, `DEVICE_*`, имя образа и периферийные
  параметры.
- Релейный модуль требует `RELAY_PIN`, модуль датчика — `ONE_WIRE_PIN`; оба не
  знают, какая плата задала периферийный пин.

Для ESP-01 окружение передаёт `RELAY_PIN=0`. Для D1 mini оно передаёт символьное
`RELAY_PIN=D1`; variant платы из Arduino core преобразует его в GPIO5.
Для DS18B20 окружение ESP-01 передаёт `ONE_WIRE_PIN=2`, а D1 mini — `D4`;
оба обозначения соответствуют GPIO2, но явные флаги сохраняют распиновку платы.

Первоначально окружение D1 mini использовало D2/GPIO4. Перед релизом 4.2.0
выход перенесён на D1/GPIO5 по фактическому подключению платы; разделение
профиля и типа устройства позволило сделать это только конфигурацией окружения.

## Последствия

Один модуль реле собирается для разных плат без `#ifdef` по их именам. Новая плата требует
своего профиля и конечного окружения, а её сборка добавляется в CI и release workflow.
Ошибка в релейном окружении без `RELAY_PIN` или окружении датчика без
`ONE_WIRE_PIN` останавливается на этапе компиляции.
