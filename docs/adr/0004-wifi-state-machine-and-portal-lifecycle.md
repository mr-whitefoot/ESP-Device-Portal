# 0004. Автомат Wi-Fi и жизненный цикл портала

Статус: принято.

## Контекст

GyverPortal включает captive portal только если `portal.start()` вызван в
режиме ровно `WIFI_AP`. Одновременно ESP8266 использует одно радио для AP и
STA, а подключение при слабом сигнале может не состояться в `WIFI_AP_STA`.

## Решение

Отделить решение от SDK: `wifi_state.h` возвращает действие, `core_wifi.h`
его исполняет. Первый подъём AP перезапускает портал; неудачная повторная
попытка возвращает чистый AP без перезапуска. `AP_STA` сохраняется только пока
у точки есть клиент, иначе попытка идёт в чистом STA. Wi-Fi persistence
выключена, credentials передаются явно.

## Последствия

Captive portal не теряется между повторами, а устройство может вернуться в
сеть после разрыва. Закрытие AP определяется наличием клиента точки, а не
HTTP-активностью портала. Порядок `corewifi::begin()` → `portalStart()`
обязателен.
