# 0001. Типизированные настройки и явные миграции

Статус: принято.

## Контекст

Двоичный снимок C++-структуры в EEPROM меняет раскладку при добавлении поля и
делает обновление прошивки разрушительным. Прямые вызовы GyverDB также мешают
native-тестам и замене хранилища.

## Решение

Использовать узкий слой `lib/settings` с типами `bool`, `int32`, `float` и
строкой. Каждый параметр хранится отдельно под compile-time хэшем стабильного
имени. `defineX` создаёт только отсутствующий параметр. Несовместимые изменения
оформляются веткой миграции по `sys.schema`; двоичные блобы запрещены.

## Последствия

Добавление параметра не сбрасывает остальные настройки, а память можно
заменить native-бэкендом в тестах. Переименование ключа несовместимо само по
себе и требует миграции. Контракт строкового буфера обязан соблюдаться всеми
бэкендами.
