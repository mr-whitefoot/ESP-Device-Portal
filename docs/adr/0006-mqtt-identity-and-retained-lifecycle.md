# 0006. Идентичность MQTT и retained-сообщения

Статус: принято.

## Контекст

Одинаковые client ID вытесняют сессию друг друга. Home Assistant не переносит
изменение `uniq_id` и `object_id` на существующую сущность, а старые retained
топики после переименования оставляют «призраки».

## Решение

Client ID строится из читаемой части имени и chip ID, `uniq_id` — из chip ID
и компонента. Discovery, state и availability публикуются retained, для
доступности задаётся Last Will. При переименовании прежнее имя сохраняется до
следующего подключения; старые топики снимаются пустым retained payload после
того, как завещание прежней сессии успело сработать. Смена идентичности HA
оформляется одноразовой миграцией.

## Последствия

Несколько одинаковых устройств сосуществуют, HA получает состояние сразу и
не хранит старую сущность бесконечно. Миграция требует отложенных шагов и
состояния в настройках, чтобы продолжиться после обрыва питания или отсутствия
брокера.
