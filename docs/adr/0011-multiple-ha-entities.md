# 0011. Одно физическое устройство может публиковать несколько HA-сущностей

Статус: принято.

## Контекст

Первоначальный контракт предполагал одну сущность Home Assistant на прошивку:
один discovery topic, один command topic и один callback MQTT-транспорта. Банк
из восьми реле остаётся одним физическим устройством и одной статически выбранной
реализацией, но должен предоставить восемь независимо управляемых switch-сущностей.

Пользовательские подписи каналов меняются. Если использовать их в топиках или
`uniq_id`, обычное переименование оставит retained-конфиги и дубликаты в реестре
Home Assistant.

## Решение

- Статический контракт устройства объявляет число сущностей, стабильный
  `entityId`, отображаемое имя и принимает индекс в discovery/command методах.
- Число сущностей ограничено восемью, поэтому MQTT использует статические
  таблицы без динамического массива и runtime-полиморфизма.
- Односущностные реализации возвращают одну сущность и сохраняют прежние
  топики, `uniq_id` и `object_id` без миграции.
- У банка стабильные ID `relay_1` ... `relay_8`; пользовательская подпись
  влияет только на поле `name` discovery.
- Discovery и command topic банка содержат дополнительный сегмент сущности.
  State и availability общие для физического устройства; state содержит JSON
  всех каналов.
- MQTT-адаптер хранит до восьми точных подписок и ставит в очередь пару
  «индекс подписки + payload». Пользовательские callback-и по-прежнему
  выполняются только из обычного `loop()`.

## Последствия

Новые многоканальные устройства можно добавлять без собственного MQTT-клиента
и без копирования retained/discovery lifecycle. Цена -- небольшой постоянный
рост RAM и флеша одноканальных ESP-01. Поэтому общий контракт проверяется
сборкой ESP-01 и его жёстким OTA-пределом при каждом изменении.

Смена подписи канала не меняет идентичность сущности. Смена стабильного
`entityId`, порядка каналов или структуры многосущностных топиков считается
несовместимой и требует явной MQTT-миграции.
